# 在线小工具站 · 选型决策表

> 目标：把「GitHub 上的桌面小工具」筛选成「能挂在网站上、免费给所有人直接用的功能」。
> 判据只有两条：**① 办公里用得多不多（频率）**；**② 能不能纯浏览器跑（可行性）**。
> 说明：★=频率，◆=网页可行性。数据基于 2026-11 的浏览器能力（Chrome/Edge 最新版、Safari 部分受限）。

---

## 一、核心结论（一句话版）

- **能全免费、零后端成本做的**：PDF 处理、图片转换压缩、文本/数据格式化、单位换算、二维码、颜色工具、简易音视频裁剪。
- **能做但有代价的**：OCR（首次要下 10–20MB 中文模型）、视频转码（ffmpeg.wasm 慢，只适合小文件）、大 PDF（>200MB 容易爆内存）。
- **网页做不了、别硬做的**：Word/Excel/PPT ↔ PDF 的高保真互转、系统级工具（启动器、剪贴板历史、文件搜索、局域网传输）、批量重命名。

### 第三梯队：办公高频但「网页形态不合适」，建议不做或换形态

| 功能 | 对应开源项目 | 为什么不做 |
|---|---|---|
| 启动器 / 全局搜索（空格呼出） | Flow.Launcher、PowerToys Run | 本质是常驻系统级快捷键，网页没有这个权限 |
| 剪贴板历史 | CopyQ | 同上，浏览器无法长期监听系统剪贴板 |
| 截图 / 录屏 / GIF 录制桌面 | ShareX | `getDisplayMedia` 可以录屏，但要每次授权，体验远不如桌面软件；可做「网页内录屏」作为补充 |
| 局域网/跨设备传文件 | LocalSend | 需要双方装同一 App；网页可用 WebRTC 做 P2P 传文件，但依赖信令服务器，复杂度高 |
| 批量重命名 | PowerRename、Everything | 浏览器只能通过目录授权操作，且无法改名；只能做「生成改名规则 + 导出脚本」 |
| 硬件检测 / 清理 C 盘 / 驱动 | ToolKnit 部分工具 | 无系统权限 |
| 视频压制 / 大文件转码 | HandBrake | 浏览器性能与内存不允许，用户会以为「网站坏了」 |
| 流程图 / 白板 | drawio-desktop | 已有成熟在线产品（draw.io 本身），自研性价比极低，可直接外链 |

## 三、MVP 建议（第一个版本做这 12 个）

优先顺序按「做起来快 + 用户真的会用 + 能带来自然搜索流量」：

1. PDF 合并
2. PDF 拆分
3. PDF 压缩
4. PDF 转图片（PNG/JPG）
5. 图片转 PDF
6. 图片格式转换（含 HEIC → JPG，这是搜索量很大的刚需）
7. 图片压缩（目标体积）
8. 图片批量缩放
9. JSON 格式化
10. 二维码生成
11. Base64 / URL 编解码
12. 时间戳转换

这 12 个全部可以**纯前端、零服务器成本**上线，且每个都是独立的高搜索意图词，对做 SEO 引流很友好。

## 四、技术形态建议

**推荐架构：纯静态站点 + 全部浏览器内计算**

- 前端：任意（Next.js / Vite + React / Astro 都行），部署到 Cloudflare Pages、Vercel、Netlify，静态托管基本免费。
- 核心库：`pdf-lib`、`pdfjs-dist`、`browser-image-compression`、`libheif-js`、`ffmpeg.wasm`、`tesseract.js`、`qrcode`、`jsQR`、`browser-fs-access`。
- 关键配置：如果用 ffmpeg.wasm 多线程，需要站点返回 `Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: require-corp`；否则只能跑单线程版。
- 每个工具一个独立路由 `/tools/pdf-merge`，方便 SEO 和被分享；工具页要有「文件不上传、全程本地」的明确说明，这是对同类在线工具最大的差异化。

**什么时候才需要后端**

只有三类需要：① 高保真 Office ↔ PDF（LibreOffice）；② 超大文件/视频转码；③ 需要账号、历史记录、付费墙。这三类都会带来服务器成本和滥用风险，建议放到第二阶段，并且用队列 + 限额 + 定时清理文件来控制。

## 五、风险与注意事项

1. **隐私承诺要写死**：既然主打本地处理，就不要偷偷上传；一旦有后端转换的功能，必须在页面上明确区分标注。
2. **文件大小上限要写在界面上**，并在超限时给出友好提示，否则用户会认为工具坏了。
3. **版权与许可证**：参考 Stirling-PDF 的实现思路没问题，但直接复用其代码要注意其非标准许可；AGPL 项目（ConvertX、VERT）的代码若修改并对外提供服务需要开源。纯前端自研的库（pdf-lib 是 MIT、tesseract.js 是 Apache-2.0、ffmpeg.wasm 是 MIT）可以放心商用。
4. **移动端适配**：办公场景下手机访问占比不低（尤其图片转换、二维码），至少保证可用。
5. **广告与免费**：「免费给大家用」意味着要靠广告或赞助覆盖域名/CDN 成本；纯静态方案成本极低，这反而是个优势。
