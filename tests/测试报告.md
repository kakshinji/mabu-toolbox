## 一、测试方法

不是「点开页面看有没有报错」，而是**真实文件进、真实文件出**：

1. 用 Python 生成测试样本（PDF、PNG、JPG、WebP、DOCX、JSON、TXT、Markdown，以及损坏文件、超大图、1×1 图、透明图、伪 docx）；
2. Puppeteer 打开每个工具页，拖入真实文件、修改控件、点击执行；
3. **拦截 Blob 下载**，把输出文件落盘；
4. 在 Node 侧用 `pdf-lib` 解析页数、用文件头校验图片格式与尺寸、比对标准哈希与 Base64；
5. 全程收集控制台错误与页面异常；边界用例额外要求「失败时有人能看懂的中文提示、不产出损坏文件、不卡死」。

测试脚本：

- `tests/e2e.cjs` — 功能测试（正常路径）
- `tests/edge.cjs` — 边界测试（异常路径）
- `tests/make_fixtures.py` / `tests/make_edge_fixtures.py` — 样本生成

```bash
npm run build
npm run preview                    # 另开终端
node tests/e2e.cjs                 # 功能：41 个工具
node tests/edge.cjs                # 边界：33 个用例
node tests/e2e.cjs --only=hash,ocr # 只跑指定工具
```

## 三、发现的真实缺陷（已修复）

### BUG-1｜哈希计算完全不可用（严重）

- **工具**：哈希计算
- **现象**：任意算法都报 `Failed to execute 'digest' on 'SubtleCrypto': Algorithm: Unrecognized name`
- **原因**：调用 WebCrypto 时把算法名做了 `algo.replace('-', '')`，传进去的是 `SHA256`，而标准要求 `SHA-256`。
- **修复**：直接传 `SHA-256` / `SHA-384` / `SHA-512`（`src/utils/hash.ts`）。
- **验证**：`abc` 的 SHA-256 现在返回标准值 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`。

### BUG-2｜Word 转 PDF 遇到中文直接失败（严重）

- **工具**：Word 转 PDF
- **现象**：含中文的 DOCX 转换抛错 `WinAnsi cannot encode "第"`，**整个转换中断，不产出任何文件**。
- **原因**：内置 Helvetica 使用 WinAnsi 编码，无法写入中文；`page.drawText` 抛异常后没有降级处理。
- **修复**：
  1. 逐字符探测可编码性，不可编码的字符替换为 `·` 并计数；
  2. 转换继续完成并产出 PDF；
  3. 页面明确提示「已跳过 N 个字符」，并引导需要保真时用桌面版 LibreOffice / WPS。
- **验证**：中文 DOCX 现在能生成 1 页 PDF，并显示跳过字符数。
- **遗留限制**：中文内容仍会丢失（这是纯前端不嵌入 CJK 字体的必然结果），已在 UI 与 README 中如实标注。

### BUG-3｜中文 OCR 无法使用（严重）

- **工具**：图片文字识别 OCR
- **现象**：点击识别后一直失败，控制台 `TypeError: Failed to fetch`。
- **原因**：代码把语言模型地址硬编码为 `tessdata.projectnaptha.com`，该域名在当前网络环境不可达；同时 tesseract.js v5 的类型声明缺少 `loadLanguage` / `initialize`，早期写法也无法按语言切换模型目录。
- **修复**：移除自定义 `langPath`，交回 tesseract.js v5 内置的 jsDelivr 源（`@tesseract.js-data`），中英文模型分别自动加载。
- **验证**：网络面板确认 `chi_sim.traineddata.gz` 与 `eng.traineddata.gz` 均 200，识别返回文本，控制台零错误。

### BUG-4｜Markdown 预览的排版样式未生效（一般）

- **工具**：Markdown 预览
- **现象**：预览区用的是旧的 `prose-sm` + 一长串任意值选择器，和全站新设计系统不匹配，标题/列表样式实际未按预期渲染。
- **修复**：统一改用 `src/styles.css` 里的 `.prose-tool` 排版类。
- **验证**：`# 标题` 渲染为 `<h1>`、`- a` 渲染为 `<li>`。

## 三·B、边界测试发现的真实缺陷（第二轮，已修复）

### BUG-5｜正则可被灾难性回溯拖死整个页面（严重）

- **工具**：正则测试
- **现象**：输入 `(a+)+$` 搭配 40 个 `a` + `!` 后，**整个标签页无响应**，浏览器报 `Runtime.callFunctionOn timed out`，用户只能强杀页面。
- **原因**：正则匹配在 `useMemo` 里同步执行，堵塞主线程；`guard > 5000` 只防死循环，防不住指数级回溯。
- **修复**：
  1. 新建 `src/utils/regexWorker.ts`，把匹配逻辑放进 Web Worker；
  2. 主线程 1.5s 超时，超时即 `terminate()` 掉 worker 并提示「表达式过于复杂或存在灾难性回溯，已中止计算」；
  3. 匹配结果上限 2000 条并标注「已截断」。
- **验证**：同一输入下页面保持响应，2.5s 内返回中文提示。

### BUG-6｜损坏/伪造的图片仍会被当成有效文件处理（严重）

- **工具**：图片格式转换、压缩、缩放、水印、去底、拼接
- **现象**：扩展名是 `.png`、内容只有 PNG 文件头的坏文件，会进入转换流程；`createImageBitmap` 部分解码成功时甚至产出 0×0 或异常的图片。
- **原因**：`toBitmap` 没有校验解码后的尺寸和文件大小，异常路径被吞掉。
- **修复**（`src/utils/image.ts`）：
  1. 0 字节文件直接拒绝；
  2. 解码后校验宽高必须 > 0；
  3. 新增 8000 万像素上限，超限给出明确提示而不是把内存吃满；
  4. 解码失败统一抛「图片数据损坏或格式不受支持」。
- **验证**：损坏 PNG 不再产出任何文件，页面显示中文错误。

### BUG-7｜`-5` 这类负数页码范围被误读成 `1-5`（一般）

- **工具**：PDF 拆分、PDF 旋转（共用 `parsePageRanges`）
- **现象**：输入 `-5` 期望「无效」，实际被解析为第 1~5 页，**静默产出了用户没想要的 PDF**。
- **原因**：正则 `/^(\d+)?\s*-\s*(\d+)?$/` 中前后两侧都可选，`-5` 命中「start 缺省 = 1、end = 5」。
- **修复**：显式跳过 `^-\d+$` 和单独的 `-`；`5-`（第 5 页到末尾）仍然有效。若最终没有任何有效范围，抛出「没有有效的页码范围」。
- **验证**：`-5` 不再产出文件；`3-`、`1-2,3-` 行为不变。

### BUG-8｜PDF 错误提示是英文堆栈，用户看不懂（一般）

- **工具**：所有 PDF 工具（合并、拆分、压缩、转图片、转文本、旋转、水印、页码、加密）
- **现象**：损坏 PDF 时页面显示 `Invalid PDF structure` 之类英文原文，或干脆没有提示。
- **原因**：各工具直接 `e.message` 透传。
- **修复**：新增 `describePdfError()`（`src/utils/pdf.ts`），按错误类型映射成中文：
  空文件 / 不是有效 PDF / 已加密 / 内存不足 / 其他兜底。
  同时在 `loadPdf` 增加 0 字节与 `%PDF-` 文件头校验。
- **验证**：损坏 PDF 显示「这个文件不是有效的 PDF（可能缺少 %PDF 文件头）」。
- **附带修复**：解密未加密的 PDF 时，明确提示「该 PDF 没有设置打开密码，无需解密」，而不是抛原始错误。

### BUG-9｜0 字节文件可以加入处理队列（一般）

- **工具**：图片转 PDF、图片格式转换
- **现象**：空文件进入列表后按钮仍可点，点了才失败，且列表显示一个 0 B 的条目。
- **修复**：上传时过滤 0 字节文件并提示「N 个文件为空（0 字节），已忽略：xxx」。
- **验证**：空文件被拦截，按钮保持禁用。

## 三·C、移动端测试发现的真实缺陷（第三轮，已修复）

测试环境：iPhone 13（390×844，DPR 3）、iPhone SE（375×667）、Android 小屏（360×740），
均开启触屏模拟 + 移动端 UA。

### BUG-10｜移动端输入框字号过小，iOS 会自动放大页面（严重）

- **影响范围**：全部含表单的工具（约 30 个）
- **现象**：输入框/文本域字号 13–14px。iOS Safari 在聚焦字号 < 16px 的输入框时会**自动放大整个页面**，用户点一下输入框页面就"跳一下"，体验很差且容易误触。
- **原因**：桌面设计为了紧凑用了 13px。
- **修复**（`src/styles.css` 的 `@media (max-width: 640px)`）：
  `.input` / `textarea` / `select` 统一 16px，并顺带把最小高度提到 44px。
- **验证**：所有工具页 `输入控件字号 ≥16px` 检查通过。

### BUG-11｜移动端触控目标普遍小于 44px（严重）

- **现象**：实测多个核心控件的可点击区域远小于 Apple HIG 建议的 44×44：
  - 顶部搜索按钮 41×36、菜单按钮 36×36
  - 主行动按钮高度 36–38px
  - 分段控件（PNG/JPG、缩进选项）40px
  - 分类 chip / 预设 chip 40px
  - 滑块热区仅 16px 高
  - 色阶色块宽度 36px
- **后果**：手指点按经常"点不中"或点错相邻项，尤其分段控件一排紧挨着。
- **修复**（`src/styles.css` + `src/App.tsx` + `src/tools/pages/ColorTool.tsx`）：
  1. 移动端所有 `button` / `select` / chip 最小高度 44px；
  2. 顶部搜索与菜单按钮改为 44×44（桌面端仍保持紧凑的 36px）；
  3. `.btn` 移动端最小高度 44px；
  4. 滑块改成"轨道 6px + 拇指 26px + 热区 44px"；
  5. 色阶色块加 `.swatch-button` 保证最小宽度 44px；
  6. `@media (hover: none)` 下不再隐藏"悬停才出现"的操作（如移除按钮），否则触屏用户永远看不到。
- **验证**：46 个页面/设备组合的触控检查全部通过。

### 附带确认（不是缺陷）

- 移动端汉堡菜单、搜索面板（⌘K 的移动入口）、分类筛选均正常工作。
- 三个视口宽度（360 / 375 / 390）均**无横向溢出**。

## 四、测试装置本身踩的坑（不是产品问题，但值得记录）

三轮共修正 12 处测试脚本问题：

| 问题 | 表现 | 处理 |
|---|---|---|
| 应用不会自动下载 | 一直在等「自动下载」的空数组 | 改为先点「下载」按钮再取 Blob |
| `<a>` 未插入 DOM | 事件代理拿不到 `a[download]` | 改为拦截 `URL.createObjectURL` 记录 Blob |
| 缩略图混入产物 | 把预览图的 object URL 当成转换结果（曾误判「透明图转 JPG 失败」） | 只取「点击下载之后」新建的 Blob |
| hash 路由是幂等的 | `page.goto` 到只差 hash 的地址不会重新加载，注入脚本失效 | 用 `?load=xxx` 强制整页加载 |
| PDF 页数用正则猜 | pdf-lib 输出压缩对象流，正则搜不到 `/Count` | 改用 `pdf-lib` 真实解析页数 |
| 上传后输入框被替换 | 文件列表视图里 `input[type=file]` 消失，多次上传失败 | 改为一次性 drop 多文件 |
| 用例未写 `record.body` | `assertAlive` 拿到空字符串，误判崩溃 | 断言前先取 body |
| 断言用旧文案 | UI 文案改版（「处理完成（3 个文件）」→「处理完成 · 3 个文件」） | 断言改用文本片段正则 |
| 卡死用例拖垮整轮 | 正则灾难性回溯导致 runner 挂起 | 加 per-case 45s 超时 + `protocolTimeout` |
| 菜单检测取错元素 | 桌面导航与移动菜单各有一个「全部工具」，取到了隐藏的那个 | 改为「存在任一可见项」 |
| 触控目标把页脚文字链接算进去 | 页脚/面包屑 17px 高的文字链接被判定失败 | 拆分为「按钮 ≥44px」与「链接 ≥28px」两档 |
| 主体检测漏了纯输入型工具 | 颜色/时间戳等只有 `<input>`，没有 dropzone/textarea | 选择器补上 `input.input` 等 |

**教训**：测试断言要基于「可独立验证的标准值」（标准 SHA-256、精确 Base64、PDF 真实页数、44px 触控标准），而不是「看起来像」的文本匹配。

## 五、仍然存在的限制（非缺陷，已知并已告知用户）

| 限制 | 影响 | 说明 |
|---|---|---|
| Word → PDF 不含中文字形 | 中文内容被替换为 `·` | 纯前端需嵌入 20MB+ CJK 字体；已提示用桌面软件 |
| PDF 压缩后文字不可选中 | 内容变成图片 | 原理决定，UI 已说明 |
| 音视频依赖 CDN 的 ffmpeg 核心 | 首次需下载约 30MB | 网络受限时给出明确报错 |
| OCR 依赖 CDN 模型 | 首次需下载约 1.7MB/语言 | 已改为稳定的 jsDelivr 源 |
| 单图 8000 万像素上限 | 超限直接拒绝 | 超过后浏览器内存不可控，明确报错优于卡死 |
| 无头浏览器下载测试 | 不支持真实「保存到磁盘」 | 通过拦截 Blob 验证内容，等价于校验产物 |
